- **Correct:** Dispatcher logic flow traced and verified. After a suggestion pill click, the user message is appended and `st.session_state.pop("chat_suggestions", None)` (line 197) clears the widget selection before `st.rerun()`. On the next run, `pending` evaluates to `True` because `messages[-1]["role"] == "user"`, `_stream_response` streams the assistant reply, appends it, and calls `st.rerun()`. The following run renders the complete exchange with `pending == False`, reaching a stable state.

- **Correct:** `st.rerun()` count is exactly 2 per interaction, matching the expected behavior. User message → append user → rerun #1 → dispatcher streams assistant → append assistant → rerun #2 → stable. Suggestion pill → append user → pop key → rerun #1 → dispatcher streams assistant → append assistant → rerun #2 → stable. Initial report → queue system+user → rerun #1 → dispatcher streams assistant → append assistant → rerun #2 → stable.

- **Correct:** `history_cache` reuse works correctly. `_trigger_initial_report` builds a `cache_key` from `year_month`, `goal`, and active modality slugs/prices/rates (shared format with `analysis.py`). If `st.session_state.historical_cache` exists with a matching key, `cached["stats"]` is reused without recomputing (`chat.py:143–151`).

- **Correct:** `st.session_state.messages` is initialized to `[]` if absent (`chat.py:70`), so `messages` is always a list and safe for indexing/iteration.

- **Fixed:** Infinite loop on suggestion pills due to `st.pills` widget state persistence.  
  **Location:** `src/ui/chat.py:193–199` (`_render_suggestion_chips`).  
  **Issue:** `st.pills(key="chat_suggestions")` stores its selection in `st.session_state.chat_suggestions`. Appending the selected text and calling `st.rerun()` without clearing that key caused the widget to re-read the same value on the next run, re-enter the `if selected:` block, append the message again, and trigger another rerun indefinitely.  
  **Resolution:** Added `st.session_state.pop("chat_suggestions", None)` (line 197) immediately before `st.rerun()`. This removes the stored selection so the pill renders deselected on the next run, breaking the loop. Applied directly to `src/ui/chat.py`.

- **Blocker:** None. The pills infinite loop was the only critical issue and is resolved.

- **Note:** `_trim_history()` assumes `messages[0]` is the system message. This is true in all normal flows because `_trigger_initial_report` always creates it first. In the pathological edge case where `active_mods` is empty and a user somehow accumulates ≥12 messages without a system prompt, `_trim_history` would incorrectly treat a user message as the system prefix. This is extremely unlikely but could be hardened with a defensive guard (`if not messages or messages[0]["role"] != "system": return`).

- **Note:** `tests/test_chat.py` from the plan ("se viável") does not yet exist. The chat module contains non-trivial state-machine logic that would benefit from targeted unit tests, especially for `_trim_history` edge cases and `_render_suggestion_chips` behavior.

- **Note:** Clicking "Limpar chat" clears `messages`, but on the next run `messages` is empty and `active_mods` is typically truthy, so `_trigger_initial_report` fires automatically and a new initial report is generated. This is acceptable UX (the user sees a fresh report immediately), but it means "Limpar chat" and "Novo relatório" differ only in cache invalidation. If a truly empty chat pane is desired, a transient flag (e.g. `st.session_state.chat_just_cleared`) could suppress the auto-trigger for one cycle.

- **Note:** All v1.4.x AI-related session-state keys (`llm_insight_text`, `llm_insight_pending`, `llm_insight_in_flight`, `llm_insight_cancelled`) are confirmed absent across the entire `src/` tree after cleanup.
